# DECISIONS (실전 아키텍처 결정 및 개발 배경 기록)

## 001: Windows PC에서 iPhone 16e 실기기 무료 개발 경로 확립
- **결정**: React Native (Expo SDK 57, TypeScript) 채택.
- **실전 배경**: Windows 환경에서 유료 개발자 계정 없이 무료로 최신 iPhone 16e 실기기에서 개발 루프를 완성함.

## 002: 순수 PWA 대신 React Native를 선택한 전략적 이유
- **결정**: 스마트폰 앱 전문 프레임워크(React Native) 채택.
- **실전 배경**: 모바일 전문성을 100% 어필하면서도, Expo의 웹 변환 특성을 통해 PWA 배포 확장성도 확보함.

## 003: 7일 PC 유선 재서명(Sideloadly) 회피 및 Expo Go 안착
- **결정**: 무료 Apple ID 독립 설치 대신 Expo Go 영구 운영.
- **실전 배경**: 7일 재서명 만료 제약 없이 평생 무료로 구동되도록 안정화함.

## 004: 사용자 건강 배경 맞춤형 도메인 모델링
- **결정**: 2형 당뇨(180cm, 85kg, 복약 중, 1일 1~2식) 맞춤형 데이터 설계.
- **실전 배경**: 누락된 영양소를 0으로 날조하지 않고 `null` 및 `UNVERIFIED`로 관리. 로컬 타임존 엄격 적용.

## 005: 9대 영양소 순서 재배치 (나트륨 4번째 이동 및 검은선 제거)
- **결정**: 1.열량 → 2.탄수화물 → 3.당류 → 4.나트륨 → 5.식이섬유 → 6.총지방 → 7.포화지방 → 8.트랜스지방 → 9.콜레스테롤
- **실전 배경**: 나트륨을 상단 4번째 칸으로 재배치하고, 카드 중간의 구분선을 제거하여 가독성을 높임.

## 006: 2계통 탭 입력 분리 및 비식품 가드레일
- **결정**: 모달 최상단에 `[사진 모드]`와 `[음식명 텍스트 모드]`를 탭으로 분리.
- **실전 배경**: 비식품 차단 및 영양소가 0개인 식사의 저장을 막는 [방안 A]를 엄격 적용.

## 007: 모델명 404 근절 및 무지연 페일오버
- **결정**: 실제 계정에 존재하는 모델로 단일화 및 0초 즉시 우회.
- **실전 배경**: 503 과부하 발생 시 즉시 2순위로 넘겨 429 한도 차단을 원천 방지함.

## 008: 60일 임상 시드 데이터 엔진 (이스터에그 숨김)
- **결정**: 설정 모달 버전 5회 터치 시에만 샘플 데이터 생성 버튼 노출.
- **실전 배경**: 60일 치 데이터를 1초 만에 SQLite에 넣을 수 있게 하되, 대외적으로는 완전한 상용 앱으로 보이도록 은닉 처리.

## 009: 식사 형태(고형식/액체식/혼합식) 전면 폐지
- **결정**: UI 및 데이터 모델에서 식사 형태 구분을 완전 제거.
- **실전 배경**: 음식 이름만 봐도 알 수 있는 정보이며, 화면 공간을 낭비하고 사용자 피로도를 높이므로 과감히 폐지하여 식사명과 9대 영양소에 화면 집중도를 극대화함.
