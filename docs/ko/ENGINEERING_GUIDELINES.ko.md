# 소프트웨어 엔지니어링 & AI 아키텍처 가이드라인 (개발 표준)

본 문서는 AI 협업 기반 엔터프라이즈 및 모바일 소프트웨어 개발 시 준수해야 하는 공통 아키텍처, 문서화, AI 거버넌스 및 예외 처리 표준 지침서입니다.

---

## 1. 문서 관리 및 디렉터리 표준 (Documentation Architecture)

### 1.1 디렉터리 구성
- **루트 디렉터리**: 프로젝트의 대문 역할을 하는 `README.md`(대외용)와 `README.ko.md`(내부 가이드)만 배치하여 청결 유지.
- **상세 설계 및 운영 문서**: 모두 `docs/` 디렉터리 하위로 집약하고 언어별로 분리 격리.
  ```text
  project-root/
  ├── README.md                 # 심사관/면접관 열람용 공식 기술 백서 (일본어)
  ├── README.ko.md              # 개발자/내부용 통합 가이드 (한국어)
  └── docs/
      ├── ja/                   # 대외 제출용 공식 기술 문서 (취업 흔적 100% 배제)
      │   ├── DECISIONS.md      # 아키텍처 결정 기록 (ADR)
      │   ├── PROJECT_STATUS.md # 프로젝트 진척 보고서
      │   └── HANDOFF.md        # 시스템 운용 및 인수인계 사양서
      └── ko/                   # 내부 개발 및 AI 협업용 실무 문서 (*.ko.md)
  ```

### 1.2 대외 제출용(일본어)과 내부 관리용(한국어)의 완전 분리
- **일본어 문서 (대외·채용 심사용)**:
  - '취업', '면접', '포트폴리오', '과제'와 같은 학습·구직 흔적(취활 냄새)을 100% 배제.
  - 상용 엔터프라이즈 제품의 공식 기술 백서(Whitepaper) 형식으로 작성하고, 설계 근거는 ADR 형식으로 기술.
- **한국어 문서 (내부·AI 컨텍스트용)**:
  - 개발자와 AI 간의 진실의 원천(SSOT)으로 운용.
  - 실제 개발 제약, 시행착오 기록, 유지보수 요점을 솔직하고 상세하게 기록.

## 2. 소스 코드 및 주석 작성 표준 (Code Standards)

### 2.1 주석 언어 규정
- 일본 IT 기업(SI/파견/자체개발) 제출을 전제로 하므로, **소스 코드 내의 모든 주석(Docstring, 인라인 설명, 타입 힌트)은 100% 일본어**로 작성.

### 2.2 네이밍 컨벤션과 클린 코드
- 변수 및 함수명은 축약하지 않고 의도가 명확한 영어 사용 (CamelCase).
- 조기 리턴(Guard Clause)을 철저히 하여 중첩 레벨을 얕게 유지.
- 데이터 결손을 '0'이나 빈 문자열로 위조하지 않고 `null`/`None`을 명시하여 데이터 무결성 보호.

## 3. Google Gemini AI 모델 선정 및 호출 표준 (AI Integration Standards)

### 3.1 권장 모델 선정 (페일오버 페어)
- **제1우선 (주계)**: `gemini-3.8-flash` (고정밀 구조화 추론)
- **제2축퇴 (부계)**: `gemini-flash-latest` (안정적 에일리어스)
- **원칙**: 503(서버 과부하) 감지 시 무의미한 재시도로 할당량을 낭비하지 않고, 즉시 축퇴 모델로 페일오버.

### 3.2 필수 요청 파라미터 규격
- `responseMimeType: "application/json"` (구조화 출력 강제)
- `temperature: 0.1` 이하 (비즈니스 데이터의 재현성과 정확성 최우선)
- `maxOutputTokens: 1024` (불필요한 토큰 지연 및 JSON 끊김 방지)

## 4. 방탄 JSON 파싱 및 정제 기법 (Bulletproof Parsing)

LLM은 설정과 무관하게 Markdown 기호나 주석, 후행 콤마를 출력할 위험이 있으므로, 파싱 전 4단계 정규식 정제 파이프라인을 필수 적용:
1. **경계 추출**: 가장 바깥쪽 `{` 부터 `}` 까지 부분 문자열 추출 (앞뒤 인사말, 마크다운 페ンス 강제 제거).
2. **주석 제거**: `// ...` 형태의 인라인 주석을 정규식으로 제거.
3. **후행 콤마 제거**: `,\s*([}\]])` 패턴을 감지하여 닫는 괄호 앞의 콤마 자동 제거.
4. **미따옴표 키 보정**: `key:` 형태의 잘못된 JSON 키를 `"key":` 형태로 보정.

## 5. 다층 방어적 예외 처리 설계 (Defensive Architecture)

- **네트워크/통신 경계**: 타임아웃(15~30초) 설정으로 프로세스 정체 방지.
- **API 쿼터/부하 경계**: HTTP 429(Rate Limit) 감지 시 즉시 중단, HTTP 503 감지 시 축퇴 모델 전환.
- **스키마/정합성 경계**: Pydantic 스키마 검증 실패 시 구체적 에러 내용을 프로ンプ트에 재주입하는 자가 수정(Self-Correction) 루프 가동.

- 모든 개발 및 포트폴리오 자산은 무료 요금제(Free Tier)를 엄격히 준수하며, 유료 클라우드나 DB 구축 없이 로컬 파일 시스템을 최우선 활용.
