# Architecture Decision Records (ADR)

本ドキュメントは、GlucoTrackにおける主要なアーキテクチャ選定、トレードオフ、および設計方針を記録した技術文書です。

---

## ADR-001: モバイルネイティブ指向フレームワーク (Expo SDK 57 / React Native)
- **選定技術**: React Native (Expo SDK 57, TypeScript)
- **背景**: 特定OSや有償開発ライセンスへの依存を排除し、最新のiOS実機(iPhone 16e)における迅速な検証パイプラインを確立する必要があった。
- **決定理由**:
  1. Expoのトンネル通信アーキテクチャを活用し、プラットフォーム制約を越えた迅速な実機動作検証環境を構築。
  2. 純粋なWeb(PWA)と比較して、将来的なネイティブヘルスケア連携(HealthKit/BLEセンサー等)への拡張性が高く、モバイルエンジニアリングとしての信頼性を担保できる。

## ADR-002: ローカルファーストSQLiteとプライバシーハイブリッド設計
- **選定技術**: `expo-sqlite` (SQLite 3)
- **背景**: 糖尿病患者の食事記録や健康状態は機微な個人データであり、外部クラウドDBへの常時同期は漏洩リスクとインフラ維持コストを伴う。
- **決定理由**:
  1. 日常のデータ蓄積・閲覧・集計はすべて端末内SQLite(iOS標準 Data Protection準拠)に物理的・論理的に完結させ、オフライン環境でも完全動作を保証。
  2. AI画像解析時のみオンデマンドでAPIを呼び出すハイブリッド構成とし、解析後はローカルDBに格納することでプライバシーと利便性を両立。
  3. 9大栄養素をリレーショナルテーブルに分離し、欠損値を勝手に「0」と捏造せず `null` および `UNVERIFIED` として管理するデータ整合性を担保。

## ADR-003: クライアント側画像最適化によるネットワーク往復遅延の短縮
- **選定技術**: `expo-image-manipulator` による長辺800px（品質0.6）前処理
- **背景**: 48MP高画素カメラの生画像（数MB）をそのままAPI送信すると、ネットワーク遅延により快適なユーザー体験が損なわれる。
- **決定理由**:
  1. クライアント側で瞬時に長辺800pxに縮小することで、データ量を約80KBへ低減。
  2. OCR認識精度を維持しつつ、実測平均2〜4秒の高速な解析レスポンスを確立。

## ADR-004: デュアルエンジン・即時フェイルオーバー設計
- **選定技術**: `gemini-3.8-flash` (第1優先) → `gemini-flash-latest` (リトライ待機なし即時フォールバック)
- **背景**: APIの無料枠における一時的過負荷（HTTP 503）発生時、無駄な待機時間を挟むとレート制限（429）の誘発を招く。
- **決定理由**:
  1. 503検知時は待機時間を挟まず直ちに公式安定版エイリアスへフェイルオーバーし、APIクォータ消費を最小化しつつ可用性を担保。

## ADR-005: 臨床安全防壁および入力バリデーション層
- **選定技術**: `src/utils/nutritionValidator.ts` クライアントサイド・バリデーション層
- **決定理由**:
  1. 文具・家具等の非食品画像検知時 (`isFood: false`) の保存をシステムレベルで遮断。
  2. 「糖質 > 炭水化物」の生化学的矛盾検知、および急激な食後高血糖を防ぐ糖質30g以上での自動注意喚起を実装。
  3. 栄養素が全て空欄(null)の場合の保存遮断（データ完全性の義務化）。

## ADR-006: 診察連携を見据えたデータポータビリティ (CSVエクスポート)
- **選定技術**: `expo-file-system/legacy` + `expo-sharing`
- **決定理由**: 完全ローカル保管型アプリの課題である「医療機関とのデータ共有」を解決するため、保存データをワンタップで標準CSVとして書き出し、iOS共有メニュー経由で医師へ提出・バックアップできる経路を確立。

## ADR-007: ドットマトリックス・カレンダーによる認知負荷低減
- **選定技術**: 外部ライブラリ非依存のネイティブカレンダーモーダル (`CalendarModal.tsx`)
- **決定理由**:
  1. 日付セル内に数字を詰め込まず、「記録完了(緑)」「高糖質警告(黄)」のミニマルドットのみを表示。
  2. 下部の1行サマリーカードから日付ジャンプを実行する洗練されたUXを実現。

## ADR-008: 5階層の防御的プログラミングと例外処理アーキテクチャ
- **選定技術**: AbortController(12秒)、safeParseJsonパーサー、isSaving並行性ロック、トランザクションロールバック
- **背景**: 生成AIやモバイルネットワークは本質的に非決定論的(Non-deterministic)であり、不意の通信遮断、過負荷、JSON構文崩れ、ユーザーの連打等に耐えうる堅牢な例外設計が不可欠。
- **決定理由**:
  1. 【通信層】12秒タイムアウト制御により、地下鉄等の電波遮断時にアプリが無期限ハングアップする事態を防止。
  2. 【AI層】モデルの構文崩れをクライアント側正規表現で自己修復し、パースエラーによるクラッシュを完全根絶。
  3. 【データ層】SQLiteの `withTransactionAsync` により、例外発生時のデータ不整合（一部のみ保存）を自動ロールバック。
