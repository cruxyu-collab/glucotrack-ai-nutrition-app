## 📌 概要 (Overview)

**GlucoTrack** は、糖尿病食事療法における最大の障壁である**「毎食の重量測定・栄養計算に伴う入力離脱」**を解消するために設計されたiOSモバイルアプリケーションです。

食品表示ラベルのOCR解析、料理写真からのポーション推計、および料理名テキストからの高速推計を統合し、臨床上不可欠な**9大栄養素（糖類等）**を自動構造化します。

機微な健康データを保護するため、日々の食事履歴やパーソナルデータは外部DBサーバーに保管せず、**「端末内ローカルファーストSQLite (iOS標準 Data Protection準拠)」**で管理。画像解析時のみオンデマンドでエフェメラルにAPIを呼び出すハイブリッド・プライバシー設計を採用しています。

```
[ エンジニアリング特性 ]
• アーキテクチャ: ローカルファースト SQLite (端末内完結・ゼロリテンション志向)
• AIプロンプトガバナンス: JSON Schema強制(application/json)および多層バリデーション
• 応答パフォーマンス: クライアント側画像前処理(800px)により実測平均 2〜4秒 を確立
• 医療データ連携: 診察時の主治医提出を想定したBOM付き標準 CSV エクスポート機能を完備
• 障害耐性: API一時過負荷(503)を回避する2段階・リトライ待機なし即時フェイルオーバー設計
```

## 🛠 技術的工夫とアーキテクチャ設計 (Engineering Highlights)

### 1. クライアント側画像最適化によるネットワーク遅延の低減
iPhone 16eの高画素生画像をそのまま送信せず、`expo-image-manipulator` を用いて端末側で長辺800px（品質0.6）へ圧縮。ペイロードを約80KBへ低減し、文字認識精度を保持したまま**実測平均2〜4秒の推論往復時間**を達成しました。

### 2. 2段階・即時フェイルオーバー設計
主モデル `gemini-3.8-flash` の一時的過負荷（HTTP 503）検知時、リトライ待機時間を挟まず直ちに公式安定版 `gemini-flash-latest` へ切り替える単方向スイッチ機構を実装。不要な再試行によるレート制限（429）を防止しています。

### 3. 多層データ整合性バリデーション層 (Validation Layer)
- **非食品検知ガードレール**: 文具等の非食品画像判定時 (`isFood: false`)、保存をシステム遮断。
- **生化学的矛盾検知**: 「糖類 > 炭水化物」などの論理破綻を検知して警告を発火。
- **高糖類注意アラート**: 急激な食後高血糖リスクに配慮した注意喚起。
- **データ完全性の保証**: 不明項目を勝手に「0」と捏造せず、`null` および `UNVERIFIED` として管理。
